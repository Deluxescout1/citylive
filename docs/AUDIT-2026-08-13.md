# CityLive audit — 2026-08-13

A whole-project sweep for bugs, dead code and mislabelling. The method is deliberately
**mechanical**: each of this engine's known recurring fault classes is turned into a
derivation over the canonical `org.citylive.wallpaper/contents/js/city.js`, so a fault is
found by a predicate rather than by reading 65,339 lines and hoping. Scripts live in the
session scratchpad; each sweep records what it proved, not just that it ran.

> 📁 The render harnesses this audit cites (`qml-godwars-arc`, `qml-gammaray-arc`, `qml-leaf-*`) are
> **session scratch, not product**, so when the work was committed they were moved out of `desktop/`
> (where an Electron glob would have shipped them) into `.scratch/`, which is gitignored. Paths below
> point there.

## Sweep 1 — arity mismatch, both directions

The `nowDate()` class: `nowDate(t)` took no argument while five callers passed one, so every
release failed on an eclipse day.

**1a — call site passes MORE args than the declaration takes.** 1,390 top-level functions
scanned. Two hits, both false positives: `sig` at L23064 and L58943 are *local* variables
(`var sig=disSig(...)`, `var sig=APOC_SIG[curDeath]`) shadowing the global `sig(now,ph)`.

**1b — call site OMITS a param the body reads unguarded.** Eight candidates, **all eight
guarded at the consumer**:

| Function | Param | Guard |
|---|---|---|
| `drawHorse` | `rid` | `rid==null?kind:rid\|0` |
| `walkMat` | `earthen` | `curVillage\|\|earthen` |
| `drawTree` | `swayOn` | `swayOn?…:0` |
| `drawPackIce` | `wBot` | `wBot==null?HORIZON:wBot` |
| `drawRsFigure` | `pid` | `drawRsFlair` opens `if(pid==null) return;` |
| `drawDamageScorch(Y)` | `dust` | `scorchCol` uses `dust?…:…` |
| `drawTitan` | `gait` | `kaijuShape` uses `(gait==null)?now*0.00016:gait` |

**Result: clean.** The arity class is swept.

`DEATHS*` pool must reach a renderer, either via an `if(curDeath==="k")` branch in
`drawApocalypseBody` or via an `APOC_X`/`APOC_X_BACK`/`APOC_X_FRONT` table entry.

- Pools found: `DEATHS` (12), `RS_DEATHS` (5), `DEATHS_SPECIAL` (6), `DEATHS_NEW` (13),
  `DEATHS_V3` (12) → **43 distinct keys**.
- Keys with no `DEATH_LABEL` entry: **none**.
- Keys with no reachable renderer: **none — 43 / 43 dispatch.**

Four keys (`glassrain`, `plague`, `ragnarok`, `thetitans`) hold *both* a hard `curDeath===`
comparison and a table entry. Checked for the double-render fault ("there were literally 3
of them on screen"): every one of those comparisons is in a *different subsystem* (building
collapse, sky tint, ground-hit predicates), not a second renderer. **Clean.**

## Sweep 6 — real seconds inside a 201-minute arc 🔴 **BUG FOUND**

### The class

`apocMs` runs `0 → APOC_BAND*GROW_CYCLE` = `0.02 × 604,800,000` = **12,096,000 ms
(201.6 min)**. Endings whose constants are authored in *real seconds* must be stretched
across that arc by `apocSpanMs()`, or the whole event is over in the first seconds and the
remaining three-plus hours is one frozen frame. `city.js` documents this at L51541 and fixes
it for nine endings — and the note itself names the class as *"every ending whose constants
are authored in real seconds"*.

### The finding

`apocSpanMs()` returns 0 for anything not in its switch, and L63302 only remaps when the
span is non-zero:

```js
if(_span>0 && cityPhase==="apoc") apocMs=Math.round(cityApoc*_span);
```

**Six endings declare real-second constants, read `apocMs` against them, and are not in the
table.** Their entire arc completes inside the first ~1% of the apocalypse:

| Ending | Authored span | Completes at cityApoc | …of a 201.6-min arc | Frozen frame after |
|---|---|---|---|---|
| `ninetails` | `FOX_ARRIVE_MS`+`FOX_WIPE_MS` = 14.2 s | 0.00117 | **14.2 s** | 3 h 21 m |
| `banwave` | `BAN_WAIT_MS`+`BAN_WIPE_MS` = 34 s | 0.0028 | **34 s** | 3 h 21 m |
| `godwars` | `GW_WAIT_MS`+`GW_CLOSE_MS` = 76 s | 0.0063 | **76 s** | 3 h 20 m |
| `logout` | `LOGOUT_WAIT_MS`+`LOGOUT_WIPE_MS` = 100 s | 0.0083 | **100 s** | 3 h 20 m |
| `wilderness` | `WILD_WAIT_MS`+`WILD_WIPE_MS` = 109 s | 0.0090 | **109 s** | 3 h 20 m |
| `massacre` | `MASS_PARTY_MS`+`MASS_WIPE_MS` = 122 s | 0.0101 | **122 s** | 3 h 19 m |

Every `apocMs` read in these six renderers was checked to be a **progress fraction**
normalised against the ending's own constants — not an animation *rate* that a remap would
slow down:

- `drawApocFox`: `apocMs/FOX_ARRIVE_MS`, `(apocMs-FOX_ARRIVE_MS*0.45)/(FOX_ARRIVE_MS*0.8)`,
  `(apocMs-FOX_ARRIVE_MS)/2200`
- `drawApocMassacre` / `massFrontR`: `apocMs/MASS_PARTY_MS`, `apocFrontR(MASS_PARTY_MS,MASS_WIPE_MS)`
- `drawApocGodWars`: `(apocMs-GW_WAIT_MS)/GW_CLOSE_MS`
- `logoutFrontR` / `wildFrontR` / `banFrontR`: all `apocFrontR(wait,wipe)`

So the remap is safe, and it is the fix the file already prescribes for this exact class.

**This is the half-fix pattern the memory names: a fix applied only where the bug was
reported. The re-timing pass caught nine (later ten, with `flood` added as a documented
ninth). These six were never added.**

### The fix

Six cases added to `apocSpanMs()`, each **derived from the ending's own constants** — the rule that
function was written under ("never a fourth number invented here, so an ending that re-times itself
later cannot silently disagree"):

```js
case "ninetails":  return FOX_ARRIVE_MS+FOX_WIPE_MS+5000;
case "massacre":   return MASS_PARTY_MS+MASS_WIPE_MS+5000;
case "logout":     return LOGOUT_WAIT_MS+LOGOUT_WIPE_MS+5000;
case "wilderness": return WILD_WAIT_MS+WILD_WIPE_MS+5000;
case "godwars":    return GW_WAIT_MS+GW_CLOSE_MS+5000;
case "banwave":    return BAN_WAIT_MS+BAN_WIPE_MS+5000;
```

**Why three audits walked past these six:** they are not in `DEATHS`. Five are the OSRS
land-triggered pool and the sixth is the fox — both deliberately kept out of that array because it is
indexed `h % DEATHS.length` and appending re-maps every past life's fate. Every sweep that walked
`DEATHS` to find real-second endings therefore missed all six.

### Two interactions checked before shipping it

1. **`APOC_LATE_FALL`** (Nick's 2026-08-10 call that all 43 level the world) reads **`cityApoc`
   only** — `apocHit`'s late-fall block gates on `cityApoc<s0` and interpolates on `cityApoc`. The
   remap cannot move when the city falls, so his decision is untouched.
2. **`apocApproachF` → `apocStruck` handoff** stays ordered for all six. The approach is
   `apocMs/APOC_APPROACH_MS[key]` and the strike is `apocMs >= <key>_WAIT_MS`; after the remap both
   scale together. `ninetails` and `massacre` hand over exactly at saturation; `logout`, `wilderness`
   and `godwars` hand over before it. `banwave` alone holds a full-intensity approach for ~8% of its
   arc before the strike (approach 5000 vs wait 8000) — ordered, and far better than the 3 real
   seconds it had before, but worth a look when that ending is next judged.

### Verified by rendering, not by arithmetic

A/B at Nick's 4K geometry, `godwars` on `falador`, three points of the arc — pre-fix engine vs fixed
engine (`.scratch/qml-godwars-arc.qml`, `QT_QPA_PLATFORM=offscreen`):

| | ap 0.05 | ap 0.45 | ap 0.85 |
|---|---|---|---|
| **pre-fix** | ordinary peaceful market day; bar reads "THE GOD WARS NOW" | blood and corpses everywhere, **no armies in frame** | finished |
| **fixed** | blue-banner army marching in from the left, defenders forming at the castle gate | armies engaged at the gate, pop 750 → 420 | finished |

The pre-fix frames are the house failure mode stated precisely: **the deaths kept coming (they are
driven by `cityApoc`) while the fight that explains them had ended 76 seconds in.** Carnage with its
source deleted — *no source, no direction ⇒ it decorates the frame instead of happening to it.*

### Gated

`desktop/test/apoc-span-retime.test.js` (3 tests). It **derives** the offenders from the death pools
rather than naming them, resolves each key to its renderer, and follows helpers to depth 4 —
`wilderness` reaches the clock as `drawApocWild → wildTaken → wildFrontR → apocFrontR`, and a version
of this test that read only renderer bodies passed on four of the six real bugs.

Two things had to be fixed in the probe itself before it was worth anything:

- **Comments are not code.** This file's prose quotes the identifiers it discusses, so a raw grep
  reported `bh`, `thetitans` and `ragnarok` as offenders on the strength of three *mentions*. The
  walker now strips comments and strings **before walking as well as before counting** — walking raw
  text also followed function names mentioned in prose as if they were call sites.
- **The shared dispatchers are excluded.** `apocHit`/`apocStruck` hold a branch for every ending, so
  a renderer asking the generic "has the city been hit here?" reaches the nuke's real-ms constants
  through them. With those cut the walk is **depth-stable: depth 3, 4 and 6 return the same answer**,
  so the result is not tuned to a depth.

**Discrimination proved both ways:** against the fixed engine 3/3 pass; with the six cases stripped
back out, the derived test names **all six** and fails 3/3. A probe whose pass and whose blind look
the same is worse than no probe.

## Sweep 4 — determinism (monitor divergence)

18 `Math.random()` call sites, all adjudicated: **`spawnFirework()` and the weather block inside
`draw()`** (snow flakes, rain, lightning). No world-generation, no simulation state, no `NOWOVR`
bypass — nothing that decides what the world *is*.

These are **screen-local ephemeral particles by documented design**: they are seeded `Math.random()*SW`
(screen width, not world), and the engine states the convention where it keeps `wetness` — *"Per-instance
state, exactly like `wetness` above it: each of Nick's three screens integrates its own."* Two consequences
are real but deliberate: fireworks and lightning are **not** synchronised across his three monitors.
Recorded here rather than changed — it is a design decision, not a defect, and reversing it is his call.

69 `Date.now()` hits, all in the live-fetch buckets (weather, air quality, Kp, flights, scores, ISS)
and in `NOWOVR!=null?NOWOVR:Date.now()` overrides. `nowDate(t)` correctly takes its argument.

## Sweep 5 — `% SW` and `drawPerson`

27 `% SW` hits. The convention is documented in the file itself at ~L43732: *"a feature is
world-anchored only if the thing it is measured against is, and `% SW` is a promise"*. Hits are in
confetti, screen-space debris and life-layer scatter — surfaces that are screen-local on purpose. The
two historical offenders this rule was written for (grey goo's 14 invented buildings and 40 people at
`((h>>>5)%SW)`) are already fixed and recorded in the endings ledger. **287** `drawPerson` call sites;
no hand-rolled 7px body found bypassing it.

## Sweep 7 — labelling 🔴 **FIXED**

`org.citylive.wallpaper/metadata.json` declared the plasmoid **`Version: 2.0.2`** — the version last
set in the 2.x era, while the project shipped 3.0 → 4.0.0 (git tags run to `v4.0.0`, and
`desktop/package.json` is `4.0.0`). KDE shows that string as the wallpaper's version, so the installed
plugin has been mislabelled by two major versions for the whole 3.x and 4.x line. **Set to `4.0.0`**
to match the last cut tag and `package.json`.

`desktop/package.json` at `4.0.0` is **correct, not stale**: v4.1.0 is prepared but deliberately not
cut (`docs/RELEASE-v4.1.0.md`), blocked on credentials. Left alone.

## Open findings — recorded, NOT changed

Each of these is a judgement call about behaviour rather than a defect with one right answer.

1. **The approach signature is real-seconds on the 26 arc-native endings.** Same class as the bug
   above, one level down. `apocApproachF()` is `apocMs/(APOC_APPROACH_MS[key]||9000)`, but for endings
   that are arc-native (`APOC_STRIKE_AP`) `apocSpanMs()` is 0, so `apocMs` stays raw and the approach
   **saturates in 9 real seconds and then holds at full intensity** until the strike — e.g. `gammaray`
   strikes at `cityApoc 0.10`, i.e. 20 minutes in. The omen does not build; it snaps on. Not fixed
   here because it changes 26 endings at once and would be impossible to judge alongside six timing
   rows. The natural derived fix is to express the approach against the key's own
   `APOC_STRIKE_AP` when the span is 0.
2. **Eight genuinely dead functions**, unreferenced anywhere in the repo:
   `K0_1` · `hyruleSolo` · `hyruleRotate` · `ganonStage` · `damBayAt` · `floodWaveEdge` ·
   `swarmDensityAt` · `logoutGone`. Proposed for deletion, deliberately **not** deleted in the same
   pass as a behaviour fix.
3. ⚠ **`hyruleSolo`/`hyruleRotate` may be an inert FEATURE, not dead code** — worth one look before
   deleting. They carry a comment describing behaviour that never runs: *"On a single screen the whole
   geography would be ten regions in 776 px — 70 px each, unreadable. So a solo screen builds the
   castle core always, and rotates ONE secondary region through the same slot, changing with the
   life."* Nothing calls either. On Nick's three-monitor world `SW/WW ≈ 0.28` so `hyruleSolo()` would
   be false anyway — but **every single-monitor user (the whole Windows build) is the case this was
   written for**, and they get the unreadable ten-regions layout it was meant to prevent.
4. **Fireworks and lightning are not monitor-synchronised** (Sweep 4). Design decision; reversible by
   scripting them from a world hash if he wants them to agree across the three screens.

## Coverage — what this audit did NOT check

Stated plainly, because a silent "audited everything" is the failure mode here.

- **Covered:** the canonical engine's dispatch tables, function arity, orphans, determinism,
  apocalypse timing, `% SW`/`drawPerson` conventions, version labelling, stray files.
- **NOT covered:** the 20 land renderers' *visual* correctness (the relief metric has stopped
  discriminating, and this audit rendered only `falador`); per-land life distributions; performance
  (no timing pass was run — the change adds no per-frame work, it only remaps one scalar); the

  chronicle/almanac replay paths.

# ROUND 2 — the open findings, resolved

Everything under "Open findings — recorded, NOT changed" above has now been acted on. Two were fixed,
one was resolved as *not mine to guess*, and one was diagnosed further but deliberately left unfixed.

## 1. The approach signature was real-seconds on the 26 arc-native endings ✅ **FIXED**

`apocApproachF()` was `apocMs/(APOC_APPROACH_MS[key]||9000)`. That is only a *fraction* if `apocMs` has
been remapped onto the arc — and for the 26 arc-native endings it has not. `gammaray` strikes at
`cityApoc` 0.10 (twenty minutes in) and its approach reached full after **eight real seconds**, then
held. An omen that does not build is not an omen, it is a state.

**Derived, not hand-listed:** an arc-native ending already declares where it strikes
(`APOC_STRIKE_AP`; `bh` keeps its own `BH_FORM_AP`), so the approach is expressed against that and
cannot drift from the moment it hands over to.

**And the table stays live for all 43.** Running the omen 0→1 across the whole pre-strike window would
have made `APOC_APPROACH_MS` dead for 26 rows — "absence is not a decision" in a new place — and would
have discarded what it encodes (*"the close-range ends get SHORT approaches on purpose"*). The window is
each ending's own constant **as a fraction of the table's own maximum**, so the authored contrast between
a long cosmic dread and a short close-range one survives, with no invented number.

Ordering verified for every arc-native ending — the approach completes at or before the strike:

| | `gammaray` | `thepit` | `bh` | `ragnarok` | `bloodmoon` | `thefamine` |
|---|---|---|---|---|---|---|
| strikes at ap | 0.10 | 0.26 | 0.18 | 0.35 | 0.40 | 0.45 |
| omen full at ap | 0.058 | 0.130 | 0.129 | 0.275 | 0.372 | 0.45 (hands over exactly) |
| **before the fix** | 0.0007 | 0.0007 | 0.0008 | 0.0009 | 0.0011 | 0.0012 |

Rendered `gammaray` on `mesa` at ap 0.01 / 0.035 / 0.09 (`.scratch/qml-gammaray-arc.qml`): **13.7% of the
frame changes across the build** where before the fix those frames were the same omen at full strength.

## 2. Eight dead functions → **six deleted, two kept on purpose**

Deleted: `K0_1` · `ganonStage` · `damBayAt` · `floodWaveEdge` · `swarmDensityAt` · `logoutGone`.
Top-level function count asserted **1391 → 1385, exactly −6** — the single number that catches the
40-function-deletion scar. Each removal was an exact-text match asserted unique, never a span edit.

## 3. 🔴 `hyruleSolo` / `hyruleRotate` are an UNBUILT FEATURE, not dead code — **his call**

Grepped the *concept*, not the name: **no other identifier implements per-life secondary-region rotation
either.** So the answer Nick gave ("if someone only has 1 monitor then we need to keep and rotate the
important stuff") is written down and never wired. A one-monitor machine still builds the full geography
and gets exactly the *"ten regions in 776 px — 70 px each, unreadable"* mush the note says it must not.
His three-head desktop is `SW/WW ≈ 0.28` and never takes the branch, **which is why it has never once
been visible to the person reviewing it — and the whole Windows build is the case it was written for.**

**Kept and marked in the source** rather than deleted: deleting them would erase the record of a decision
he made and leave the gap indistinguishable from "nobody thought about single monitors". Wiring it is a
feature build — it needs the region list split into core/secondary and **his call on which regions share
the rotating slot** — so it is his to schedule, not mine to guess.

## 4. 🔴 The translucent slabs — **localised, still not fixed**

Narrowed hard, but not to a specific fill, and I will not guess-fix a land's art.

**What is now established**, by stubbing functions from the harness and measuring a single sky row:

- Not the leaf cliff. The `bg` pass renders **clean** — no slabs. (My first attribution was wrong: a
  whodrew probe found the cliff's top-light wash because I probed *inside the cliff*, not the sky. I
  changed that wash, measured **248 pixels** of difference, and reverted it — it was not the cause.)
- **Apocalypse-only:** with no apocalypse running the live pass sky is clean.
- Stub `drawApocalypse` → slabs gone. Stub `drawApocDustWall` → still there. Stub `drawApocApproach` →
  still there. **Stub `drawApocalypseBody` → gone.** So the source is inside **`drawApocFox`**.
- Ruled out within it: the 5-shell burning shroud (magenta probe: unchanged) and the nine tails (opaque
  fur, not translucent).
- Measured shape: at canvas y=250 the slab is **five nested symmetric steps** about a centre, warming
  inward — `(64,34,26,148)` base wash → `171` → `194` → `217` at the core — 23 world px per step.

⚠ **`whodrew.js` could not reproduce them at all** — node is not the runtime, and it also hardcodes
`taskbarWp: 17`, so its coordinates do not line up with a harness using `taskbarWp: 0`. The stub-and-
